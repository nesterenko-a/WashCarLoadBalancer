# 1. Random — случайное распределение

Самый простой baseline.

```text
Car → случайная мойка
```

Например:

```text
A  33%
B  33%
C  33%
```

### Зачем изучать?

Не потому что ты будешь использовать Random, а потому что это **точка сравнения**.

Если твой алгоритм не лучше Random — с ним что-то не так.

**Уровень важности:** ⭐

---

# 2. Round Robin

Распределяем по очереди:

```text
A → B → C → A → B → C
```

Или:

```text
A → B → C → D → A → B...
```

### Проблема

Не знает ничего о состоянии системы.

Если:

```text
A = свободна
B = 100% загрузка
C = свободна
```

алгоритм всё равно отправит следующую машину в B.

### Зачем изучать?

Понимание базового **статического load balancing**.

**Уровень:** ⭐

---

# 3. Least Connections

Очень известный алгоритм из балансировки серверов.

Выбираем ресурс с наименьшим количеством активных соединений.

```text
A = 5
B = 2 ← выбираем
C = 7
```

Для автомоек аналог:

> отправить машину туда, где меньше всего обслуживаемых/ожидающих автомобилей.

Но есть проблема.

```text
A:
3 машины × 5 минут

B:
2 машины × 30 минут
```

Least Connections выберет B.

Но это может быть плохим решением.

### Поэтому

Для твоей задачи **Least Connections — скорее учебная ступень**, чем конечный алгоритм.

**Уровень:** ⭐⭐

---

# 4. Shortest Queue / JSQ

Вот это уже **ключевой алгоритм для тебя**.

**Join the Shortest Queue (JSQ).**

```text
A = 7
B = 2 ← выбираем
C = 5
```

Каждый новый автомобиль присоединяется к самой короткой очереди.

Это классическая задача из **теории массового обслуживания и load balancing**.

### Что изучить

Ищи:

> **Join the Shortest Queue**

> **JSQ load balancing**

> **Shortest Queue policy**

Это одна из главных вещей, которую тебе нужно понимать.

**Уровень:** ⭐⭐⭐⭐⭐

---

# 5. Weighted JSQ

Следующий уровень.

Не просто:

```text
queue = 5
```

а:

```text
effective load =
    queue
    × average service time
    / number of servers
```

Например:

```text
             Queue   Service   Posts

Wash A         4       5 min      4
Wash B         2      20 min      2
Wash C         5       7 min      5
```

Простая очередь:

```text
B = 2 ← лучший
```

Но реальная ожидаемая нагрузка может показать:

```text
A ≈ 5 min
B ≈ 20 min
C ≈ 7 min
```

И тогда выбираем A.

### Для твоего проекта

**Это уже очень близко к реальному production-алгоритму.**

**Уровень:** ⭐⭐⭐⭐⭐

---

# 6. Power of d Choices

Очень важный класс.

Идея:

> Не обязательно знать состояние всех серверов. Можно выбрать `d` случайных ресурсов и взять лучший.

Например:

```text
10 автомоек

             ┌── Wash A
CAR ─────────┤
             └── Wash F

A = 8 машин
F = 3 машины

→ F
```

При `d = 2`:

**Power of Two Choices.**

При `d = 3`:

**Power of Three Choices.**

Обозначение:

```text
JSQ(d)
```

### Почему это интересно?

Исследования показали, что даже выбор **лучшей из двух случайно выбранных очередей** может радикально улучшать распределение нагрузки по сравнению со случайным выбором.

Это одна из фундаментальных идей современного load balancing.

**Уровень:** ⭐⭐⭐⭐⭐

---

# 7. Join-Idle-Queue — JIQ

Идея немного другая.

Вместо того чтобы постоянно искать:

> какая очередь самая короткая?

мы пытаемся найти:

> где сейчас вообще есть свободный ресурс?

Например:

```text
A ██████████
B ██████████
C ██████████
D ██░░░░░░░░
E ░░░░░░░░░░
```

Если E свободна:

```text
CAR → E
```

### Почему тебе полезно?

Для автомоек это очень естественная модель:

> **есть свободный пост → отправляем туда автомобиль.**

Но при нескольких постах и неоднородных временах обслуживания JSQ/weighted-JSQ может быть информативнее.

**Уровень:** ⭐⭐⭐

---

# 8. State-Aware / Load-Aware Balancing

Вот здесь начинается то, что я бы считал **твоей основной областью**.

Алгоритм смотрит не на один показатель, а на состояние мойки:

```text
queue
+
busy posts
+
free posts
+
service time
+
capacity
+
distance
+
car compatibility
```

Например:

```text
Score(A) =
    0.4 × QueueLoad
  + 0.2 × ServiceTime
  + 0.2 × TravelTime
  + 0.2 × Utilization
```

И:

```text
выбрать argmin(Score)
```

Это уже не один конкретный алгоритм, а **класс state-aware policies**.

**Уровень:** ⭐⭐⭐⭐⭐

# 9. Predictive Load Balancing

Очень важный следующий этап.

Обычный JSQ:

```text
Сейчас:
A = 3
B = 5

→ A
```

Predictive:

```text
Сейчас:
A = 3
B = 5

Через 15 минут:
A = 12
B = 6

→ B
```

То есть:

```text
Current State
      +
Forecast
      ↓
Decision
```

### Здесь появляются

* Time Series Forecasting
* Demand Forecasting
* Predictive Load Balancing
* Model Predictive Control

Для твоего завода это особенно интересно из-за **смен сотрудников, расписания производства и периодических пиков**.

**Уровень:** ⭐⭐⭐⭐⭐

# 10. Optimization

Следующий уровень — перестать думать:

> «какую мойку выбрать?»

и сформулировать:

> «как оптимально распределить поток автомобилей между всей сетью?»

Например:

```text
minimize:

Σ WaitingTime
+
Σ TravelTime
+
Σ ServiceTime
```

при ограничениях:

```text
capacity
compatibility
working hours
queue limits
priority
```

Здесь появляются:

* Linear Programming;
* Integer Programming;
* Mixed Integer Programming;
* Constraint Programming.

Для практики:

**Google OR-Tools.**

**Уровень:** ⭐⭐⭐⭐

---

# 11. MDP / Reinforcement Learning

Это уже верхний уровень.

Можно представить систему как:

```text
State
  ↓
Action
  ↓
New State
  ↓
Reward
```

Например:

```text
State:

A = 80%
B = 40%
C = 60%

Action:

Car → B

Reward:

- waiting time
- travel time
- congestion
```

И система учится выбирать действия.

Это:

* Markov Decision Process;
* Reinforcement Learning;
* Deep RL.

### Но я бы пока НЕ шёл сюда.

Для твоей задачи сначала нужно добиться хорошего результата с:

**JSQ → Weighted JSQ → Forecast → Optimization.**

Очень вероятно, что этого будет достаточно.

**Уровень:** ⭐⭐ на первом этапе.
